# Code quality audit, 2026-07-29

Scope: `~/Projects/tinyintent` and `~/Projects/smallintent`, both checkouts of
`github.com/the9ines/tinyintent`.

Method: every claim below was verified by executing against the code, not by
reading documentation. Where a source file and a document disagree, the file wins.

## Verdict

The architecture is sound and the security primitives are real, working code. The
application that would use them cannot start, the test suite has never run, and
the documentation describes a system two model generations out of date.

This is not a rotten codebase. It is a good design that was never once executed
end to end after its final refactor.

## What actually works

Verified by import with a valid `TINYINTENT_SECRET` set:

- `tinyintent.config` loads
- `bridge.token_manager` imports, and the security report's description of it is accurate
- `bridge.secret_validator` imports, and fail-fast validation genuinely works. With no
  secret set, config refuses to load and raises. That is correct behaviour, not a bug.
- `helpers.sandbox` imports, and `_prepare_helper_files()` exists at line 118 as claimed
- The `/shortcut/token` and `/shortcut/token/rotate` endpoints exist at lines 413 and 462

The `SECURITY_HARDENING_REPORT.md` claims about *what was built* are substantially
true. Its claims about *verification* are not. See below.

## What is broken

### 1. The application cannot start

`d27fb09` (2025-08-25) deleted `bridge/gen_client.py` (388 lines) while five files
still import it. Every HTTP-layer module dies:

```
bridge.routes.shortcut   ModuleNotFoundError: No module named 'bridge.gen_client'
bridge.routes.health     same
bridge.api_main          same
bridge.tinyrpc           same
```

**Severity: high. Effort to fix: one file.** Restoring the 388-line file from
pre-rewrite history makes all four import cleanly. This was verified, then reverted.

### 2. The test suite has never run

Two independent defects, either of which alone is fatal:

**a. Phantom module path.** 22 test files import `tinyintent.bridge`, which does not
exist. `bridge/` is top level. Introduced by `115b3bf` (2025-08-21), titled "Complete
System Cleanup & Refactoring". Because `tests/conftest.py` is one of the 22, *no test
in the repository can be collected*, including tests that do not themselves use the
bad path.

**b. Nine files are not valid Python.** Fixing (a) still leaves 20 collection errors.
Nine files fail to parse at all:

```
tests/bridge/rate_limit_test.py              SyntaxError
tests/integration/emergency_kill_test.py     IndentationError
tests/integration/gen_reliability_test.py    SyntaxError
tests/integration/bot_guard_live_test.py     SyntaxError
tests/helpers/helpers_versioning_test.py     SyntaxError
tests/helpers/helpers_capabilities_test.py   SyntaxError
tests/router/router_quality_test.py          SyntaxError
tests/router/router_override_test.py         SyntaxError
tests/router/router_async_test.py            SyntaxError
```

The cause is a botched automated find-and-replace that stripped indentation:

```python
try:
    from tinyintent.bridge.router_client import SmallIntentRouter
from tinyintent.bridge.gen_client import AsyncOllamaClient   # indentation lost
    BRIDGE_AVAILABLE = True
except ImportError as e:
```

**This is the most important finding in the audit.** A file with a syntax error
cannot execute even once. These were committed in that state. Therefore the test
suite was never run after that edit, and the "comprehensively tested" claim in
`SECURITY_HARDENING_REPORT.md` cannot be true.

**Timeline that matters:** tests broke 2025-08-21. The service broke 2025-08-25. The
security hardening commit titled "achieve production readiness" landed 2025-08-25,
four days after the test suite stopped being runnable.

### 3. Production code that does not parse

`helpers/network_monitor/health.py:115` uses `from pysnmp.hlapi import *` inside a
function. Star imports are only legal at module level, so the file cannot be loaded.

This is the same `network_monitor` helper that failed validation on every hourly
autopilot run for eleven months with `Manifest loading failed: 'list' object has no
attribute 'get'`. See `CRASH_POSTMORTEM_2026-07-29.md`.

**Severity: high.** This is shipped code, not a test.

### 4. Documentation drift

Three different model architectures are claimed across the two repos. Only one was
ever trained in each.

| Source | Claims | Actually trained | Size |
|---|---|---|---|
| smallintent `claude.md:69` | `prajjwal1/bert-tiny`, and explicitly says do not switch to DistilBERT | **bert-tiny**, `BertForSequenceClassification`, hidden 128, 2 layers | 4.19 MB |
| smallintent `claude.md:222,229,246,280,342` | DistilBERT, "<5MB, 8-bit quantized" | never trained | n/a |
| tinyintent portfolio + docs | DistilBERT | **ELECTRA small**, `google/electra-small-discriminator`, 13,549,314 params | 51.6 MB |
| `router/train_router.swift` (448 lines) | DistilBERT-class, ~66M params, targets 70-85 MB INT8 | never ran, produced no artifacts | n/a |

`smallintent/claude.md` contradicts itself inside a single file: line 69 says
bert-tiny and forbids DistilBERT; six later lines say DistilBERT.

`train.py` resolves the ambiguity. It tries backbones in order and takes the first
that loads:

```python
model_options = [
    "google/electra-small-discriminator",  # first, always succeeds
    "distilbert-base-uncased",             # fallback, never reached
    "microsoft/DialoGPT-small",
    "prajjwal1/bert-tiny"
]
```

DistilBERT was never the backbone in either repo. The shipped `SmallIntent.mlmodel`
carries `torch==2.8.0` and `coremltools` metadata, confirming the PyTorch path, and
its 51.6 MB matches ELECTRA small at FP32 (13.55M params x 4 bytes = 54 MB).

The public portfolio claims were corrected on 2026-07-29. They had been describing
SmallIntent M0's 4 MB bert-tiny model while linking to the repo that ships the 52 MB
ELECTRA model.

### 5. Dead paths

- `router/train_router.swift`, 448 lines, targets a different architecture than what
  ships and produced no artifacts on disk. No `.mlpackage`, no CreateML output.
- Five files still reference the deleted `bridge.gen_client`. Three of them point at
  `tinyintent.bridge.gen_client`, a path that never existed at all, so those were
  already broken before `d27fb09`.
- `bridge/api_routes.py`, `bridge/router_client.py` and `tinyintent.helpers.*` are
  imported by tests but do not exist.

### 6. Secrets were committed

Three live secrets were committed and were one `git push` away from a public repo.
Removed from history on 2026-07-29 before any push. See the git history rewrite of
that date. None ever reached GitHub.

Note the irony: `SECURITY_HARDENING_REPORT.md` correctly specifies 0600 permissions
and rotation for exactly the token file that was committed to a public repository.

## Effort estimate to revive

Ordered by dependency, based on what was verified:

1. Restore `bridge/gen_client.py` from history. **One file.** Makes the app importable.
2. Rewrite `tinyintent.bridge` to `bridge` across 22 test files, preserving indentation.
3. Repair the nine unparseable test files by hand. The damage is mechanical and local.
4. Fix `helpers/network_monitor/health.py:115`, move the star import to module level.
5. Resolve the missing modules the tests expect: `bridge/api_routes.py`,
   `bridge/router_client.py`, `tinyintent/helpers/`.
6. Only then can anyone state a real pass rate. **No pass rate has ever existed.**
7. Add log rotation before re-enabling either launchd job.

Steps 1 through 4 are mechanical. Step 5 is the unknown, because it is unclear whether
those modules were deleted or never written.

## Recommendation

The design is worth keeping and the security modules are genuinely good standalone
work. The honest framing for a portfolio is a well-architected prototype that was
never integration-tested, not a production-ready system.

Do not re-enable the launchd jobs until at least steps 1 and 7 are done.
